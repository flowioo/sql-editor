SQL Query Editor

1. Overview

A lightweight, fast SQL query editor with native vim editing mode. Built on Tauri v2 (Rust backend) + CodeMirror 6 (JS frontend), targeting ~10MB binary size — 20x lighter than Electron-based alternatives.

Core differentiator: vim-native editing + multi-database support + zero-latency local connections.

7. Key Technical Decisions

7.1 Why CodeMirror 6 over Monaco?

  • CM6 is modular — bundle only what you need (~50KB vs Monaco ~4MB)
  • First-class vim mode extension
  • Better performance for large documents
  • Monaco requires web workers; harder in Tauri WebView

7.2 Result Grid Strategy

For 100k+ row results, use @tanstack/virtual with a custom canvas renderer. AG Grid Community is heavier but provides sorting/filtering out of the box. Start with AG Grid, optimize later.

7.3 Streaming Large Results

// Rust: stream rows via Tauri events instead of collecting all
async fn execute_query(sql: &str, conn_id: &str) -> Result<()> {
    let mut stream = sqlx::query(sql).fetch(&pool);
    let mut batch = Vec::with_capacity(1000);
    while let Some(row) = stream.next().await {
        batch.push(row_to_json(row?));
        if batch.len() == 1000 {
            app_handle.emit("query_rows", &batch)?;
            batch.clear();
        }
    }
    app_handle.emit("query_done", batch.len())?;  // final batch + done signal
}

7.4 Schema Autocomplete Architecture

// Frontend: register schema as CodeMirror completion source
function schemaCompletionSource(context: CompletionContext) {
  const word = context.matchBefore(/[\w.]+/);
  if (!word) return null;

  const text = word.text.toLowerCase();
  const options: Completion[] = [];

  // "SELECT ... FROM ta|" → complete table names
  if (isAfterFrom(context)) {
    schema.tables
      .filter(t => t.name.startsWith(text))
      .forEach(t => options.push({
        label: t.name,
        type: "table",
        detail: t.description,        // from code annotations
        info: t.model_location         // e.g. "internal/model/user.go:15"
      }));
  }

  // "SELECT col|" → complete column names
  if (isSelectClause(context)) {
    schema.tables.flatMap(t => t.columns)
      .filter(c => c.name.startsWith(text))
      .forEach(c => options.push({
        label: c.name,
        type: "property",
        detail: c.description,         // "用户手机号" from Go struct tag
        info: c.business_context       // business meaning
      }));
  }

  return { from: word.from, options };
}

7.5 Local Schema Cache (SQLite)

Schema is persisted to a local schema_cache.db (SQLite). On app launch, load from cache instantly; on connect, optionally diff with remote. Manual refresh via toolbar button or <leader>rs (vim).

-- schema_cache.db structure
CREATE TABLE schema_snapshots (
  id          INTEGER PRIMARY KEY,
  connection  TEXT NOT NULL,          -- connection identifier
  db_name     TEXT NOT NULL,
  captured_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  schema_json TEXT NOT NULL           -- full schema as JSON blob
);

CREATE TABLE column_descriptions (
  connection  TEXT NOT NULL,
  db_name     TEXT NOT NULL,
  table_name  TEXT NOT NULL,
  column_name TEXT NOT NULL,
  description TEXT,                   -- from code annotations or manual edit
  source      TEXT,                   -- "code:go" | "code:ts" | "code:prisma" | "manual"
  file_path   TEXT,                   -- source file location
  updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (connection, db_name, table_name, column_name)
);

7.6 Code-Linked Schema Descriptions

Scan codebase model definitions → extract field comments/tags → enrich schema autocomplete with business context.

// Codebase scanner extracts descriptions from model definitions:

// Go struct tag
type User struct {
    ID        int64  `json:"id" db:"id"`
    Phone     string `json:"phone" db:"phone"`      // 用户手机号
    Nickname  string `json:"nickname" db:"nickname"` // 用户昵称
}

// TypeScript interface
interface User {
  id: number;        /** 用户ID */
  phone: string;     /** 用户手机号 */
  nickname: string;  /** 用户昵称 */
}

// Prisma schema
model User {
  id       Int    @id // 用户ID
  phone    String     /// 用户手机号
  nickname String     /// 用户昵称
}

→ Scanner maps:  table="users" column="phone" description="用户手机号" source="code:go"
→ CM6 autocomplete shows description as inline detail

7.7 AI SQL Generation via CCR

Use local CCR (Claude Code Router) as LLM proxy. Schema context + code descriptions are injected into the prompt for accurate SQL generation.

// User types NL in AI panel, gets SQL back in editor
// Prompt construction in Rust:

fn build_sql_prompt(nl_query: &str, schema: &SchemaCache, conn: &Connection) -> String {
    let schema_ctx = schema.to_compact_ddl(conn);  // "CREATE TABLE users (id INT, phone VARCHAR...)"
    let descriptions = schema.get_descriptions(conn); // column → description map

    format!(
        "You are a SQL expert. Given this schema:\n\
         {schema_ctx}\n\n\
         Column descriptions:\n{descriptions}\n\n\
         Database: {db_type}\n\n\
         Generate a single SQL query for: {nl_query}\n\
         Rules: use CTEs for complex logic, add LIMIT 100 by default."
    )
}

// CCR call: POST http://127.0.0.1:3456/v1/messages

// Response → insert into editor at cursor position

8. Milestones

  • M1 — Skeleton (Week 1-2)
    Tauri project setup, window management, tab system, basic CodeMirror editor with vim mode. SQLite single-file connection. Local schema cache (schema_cache.db) with snapshot storage.
  • M2 — Query Engine (Week 3-4)
    Connection manager, query execution, streaming results, result grid, query history. PostgreSQL + MySQL drivers. Schema cache diff-on-connect + manual refresh (<leader>rs).
  • M3 — Intelligence (Week 5-6)
    Schema autocomplete with code-linked descriptions. Codebase scanner (Go struct / TS interface / Prisma). Sidebar schema tree with business context. SSH tunnel support.
  • M4 — AI + Polish (Week 7-8)
    AI SQL generation panel (NL→SQL via CCR). Schema+descriptions injected into prompt. Export (CSV/JSON), split panes, session restore, theming, cross-platform builds.

9. Risk Assessment

RiskImpactMitigation
CM6 vim mode incomplete Medium Test 50+ vim commands early (M1). Fallback: neovim WASM as alternative.
WebView performance with large results Medium Virtual scrolling from day 1. Canvas renderer for 1M+ rows.
sqlx driver compatibility Low Abstract behind trait DatabaseDriver. Swap per-DB if needed.
Tauri v2 API churn Low Pin Tauri v2 stable. Avoid nightly features.
Codebase scanner accuracy Medium Tree-sitter grammars are mature for Go/TS. Start with regex fallback for Prisma. Incremental: add languages one at a time.
CCR unavailable / LLM timeout Low AI panel is non-blocking. Show error toast, editor still works. Retry with backoff. Configurable timeout.
